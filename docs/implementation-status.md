# Implementation status

Installed build **0.11.0** makes the Agent graph a free node canvas: compact provider tiles, ports, curved project links, dashed subagent links, status indicators, saved node dragging, pan/zoom, a minimap, Fit and Tidy up. Details opens full questions, reports, progress and source evidence in an inspector. Single clicks still open existing terminals alongside with direct input. The full suite passed 300 tests, and isolated native terminal/runtime checks passed. See [canvas verification](verification.md#agent-node-canvas-verification).

Build **0.10.0** added responsive project sections, stable columns of connected agent families and content-sized cards. Current task, questions/blockers, activity age, model, checkout and directory are visible without hovering; reported task progress and inline reports/next steps make the overview richer. Layout/browser checks cover 80 agents, variable heights, narrow split panes and keyboard geometry. See [rich graph verification](verification.md#rich-agent-graph-layout-verification).

Build **0.9.0** made the Agent graph the primary workspace, with one-click adjacent terminal attachment, project focus, activity filters, model/branch search and known parent/subagent links. Bounded provider events and task reports distinguish questions, blockers, working, recent completion, idle and unknown activity. Verified Git common directories group worktrees/subfolders with the main project; existing enrolled project/task authority stays intact. Native subagent output remains view only when it has no terminal. See [graph workspace verification](verification.md#agent-graph-workspace-verification).

Build **0.8.0** added the searchable session list: all-environment live inventory, project/task identity, provider-recorded models, distinct terminal/location labels, searchable sessions, explicit interactive/view-only access, direct xterm keyboard focus and no extra session composer. Conductor and management remain under **More**. The model index supports current and older Codex schemas plus Claude/Grok output; models are linked only through matched history. See [sessions verification](verification.md#sessions-workspace-verification).

The working tree now implements owner-selected **isolated Linux teams**, private agent checkouts/homes/browsers, restricted or offline networking, bounded managed helper requests, retained workspaces and patch export. Teams and Runtime views expose limits, parent/child relationships, controls, browser previews and partial failures. Existing host agents keep their execution mode. See the [runtime contract and remaining acceptance](plans/isolated-teams.md) and [verification evidence](verification.md#isolated-team-runtime-verification). The source is included in installed 0.8.0; runtime image and provider acceptance retain the limits recorded in verification.

The working tree adds a live **System graph** with Conductor phases and public tool activity, action receipts, agent/task/team relationships, messages and delivery, MCP contact, browser contexts and background services. Nodes open existing terminal/conversation views and retain selection, filters, zoom and inspector reading position across refresh. Managed provider launches now retain their application-supplied initial prompt; missing historical prompts are labelled unavailable. Terminal agents can inspect Conductor through `st_conductor` and use the existing scoped reporting/mailbox tools. The owner graph is never returned through agent MCP credentials. See [C4](plans/conductor-and-sessions.md#c4--system-transparency-and-terminal-coordination) and [verification](verification.md#system-graph-verification).

The source store now refuses to open or save a Markdown workspace when an active legacy `state.json` also exists. This prevents silently ignoring conversations written by an older build after migration. Both stores remain intact; reconciliation is still required before upgrading a conflicted installation. See [recovery](operations.md#conflicting-state-stores) and [P3](plans/packaging-and-recovery.md#p3--persisted-state-migration-and-diagnostics). This safeguard is installed in 0.8.0; the conflicting personal stores were reconciled through the offline recovery command.

The source command `npm run recovery:inspect` compares both stores with the migration backup without writes. An additional offline recovery command now stages and reopens a reconciled workspace, verifies private backups, checks for writers and source changes, and rolls back replacement failures. Its explicit policy retains current project display fields and archives alternatives; authority/content conflicts outside that policy are refused. Recovered coordination loops remain stopped. A prepared upgrade finisher can install the verified build and submit the original owner request through normal Conductor project dispatch, once the current chat has ended. The 0.8.0 installation and offline recovery are verified. Team activation and new provider task acceptance were not requested or attempted by this update. See [P3](plans/packaging-and-recovery.md#p3--persisted-state-migration-and-diagnostics).

## Resolved discovery error

The reported `Cannot read properties of undefined (reading 'replace')` coincided with `/api/state` returning an error. The fix at `6726db5` validates tmux rows and normalizes optional TTY values before string operations. The renderer also tolerates a missing managed title and restores the workspace after a successful retry of initial state loading.

The original malformed input row was not captured. The regression test reproduces the unsafe missing-TTY condition; it does not establish which external row first triggered the incident. After installation, the state endpoint and both approved SSH scans succeeded. [Core tests](../test/core.test.mjs) cover malformed/diagnostic tmux lines and missing TTYs. [D1](plans/discovery-and-history.md) tracks broader failure isolation; it is not a reopening of the same fixed exception.

## Output and task protocol

[transcript.mjs](../server/transcript.mjs) and the remote reader expose saved messages, commentary and tool traffic with byte-offset cursors and stable event IDs. The compact message projection remains separate for Conductor context. Reads tolerate partial JSONL writes and disclose oversized records; provider-internal reasoning and unlogged output are unavailable. [Transcript tests](../test/transcript.test.mjs) cover boundary paging and local/remote parity.

[tasks.mjs](../server/tasks.mjs) stores runtime task records privately. Agent-created tasks stay in the enrollment scope; events do not authorize launches or change CLI permissions. [conductor-policy.mjs](../server/conductor-policy.mjs) validates continuous actions against fresh active scope. Human-session controls, task state, provider response completion and process state remain distinct.
