Build it on your Mac.

Super Terminal is available as source. There is no prebuilt installer yet.

System
macOS Ventura or newer
Build tools
Node.js 22.13+, npm, Git and Python 3
Terminals
tmux, plus your installed and signed-in agent CLIs

The app bundles Electron and Node. After building, open it from Finder or Spotlight. The macOS bundle is ad hoc signed, not notarized.

Full installation documentation
Terminal · macOS
git clone https://github.com/NikoKaranatsios/super-terminal.git
cd super-terminal
brew install tmux
npm ci
npm run install:desktop
open "$HOME/Applications/Super Terminal.app"

Install the build tools listed alongside first. The tmux command uses Homebrew.

Once it opens

  1. Use New terminal to start your preferred CLI, or find an existing supported tmux session.
  2. Open Graph. Select an agent to read its work state and attach to its terminal.
  3. For remote sessions, add your SSH targets using the example connection file and SSH setup guide.

Before you install

A few honest answers.

Is this open source?

The source repository is public, but a project-wide open-source license has not been specified. Public visibility alone does not grant an open-source license.

Does this replace Codex, Claude or Grok?

No. It brings your installed agent CLIs into one workspace. You keep their sign-ins, native commands and permission flows. Provider usage and billing stay with your provider accounts; Conductor uses your Codex sign-in.

Can it control every terminal I already have open?

It can attach to supported tmux sessions. Ordinary external processes cannot have their live screen and keyboard safely adopted. Where supported history is available, you can read it in a view-only session. Discovery is limited to readable accounts and supported sockets and history formats.

Where does my data go?

Workspace records and connection settings stay on your machine. Your agent CLIs use their existing providers. Conductor requests send bounded work context through your Codex account. The desktop service listens on loopback; this public demo makes no agent or model requests.

Can I run the app on Linux or Windows?

The verified desktop installation target is macOS. A Linux packaging path exists, but full Linux desktop acceptance is not established. Windows support is not verified. This website demo works independently of the desktop app.

What if the build or a session doesn’t work?

Check Node and Python versions, confirm tmux is installed, and make sure your provider CLI works in a normal terminal. Native-module build errors may require Xcode Command Line Tools. For a bug report, include the app version, OS and redacted reproduction steps in a GitHub issue. Leave out credentials, private connection targets and transcripts.
